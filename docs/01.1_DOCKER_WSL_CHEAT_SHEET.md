### Ce document récapitule les commandes essentielles pour gérer, vérifier et utiliser l'environnement Docker natif sous WSL, sans dépendre de Docker Desktop.

---

## 1. Gestion du Service Docker (via `systemd`)

Le démon Docker tourne en arrière-plan grâce à `systemd`.

* **Vérifier l'état du service :**
~~~~bash
sudo systemctl status docker
~~~~

* **Démarrer le service manuellement (si arrêté) :**
~~~~bash
sudo systemctl start docker
~~~~

* **Arrêter le service :**
~~~~bash
sudo systemctl stop docker
~~~~

* **Activer le lancement automatique au démarrage de WSL :**
~~~~bash
sudo systemctl enable docker
~~~~

---

## 2. Vérification rapide et sans `sudo` (Idéal pour les scripts / pipelines)

Pour s'assurer que le démon répond et que le socket `/var/run/docker.sock` est bien actif sans avoir besoin de privilèges administrateur :
~~~~bash
docker info >/dev/null 2>&1 && echo "Docker est prêt"
~~~~

---

## 3. Commandes d'utilisation quotidienne (Sans `sudo`)

Grâce à l'appartenance de l'utilisateur au groupe `docker`, toutes les commandes s'exécutent directement :

* **Tester l'installation avec un conteneur éphémère :**
~~~~bash
docker run hello-world
~~~~

* **Lister les conteneurs en cours d'exécution :**
~~~~bash
docker ps
~~~~

* **Lister tous les conteneurs (actifs et arrêtés) :**
~~~~bash
docker ps -a
~~~~

* **Lister les images disponibles :**
~~~~bash
docker images
~~~~

---

## 4. Dépannage rapide (En cas de perte du socket)

Si le socket venait à ne pas répondre après une mise en veille prolongée de Windows :

1. Ouvrez un terminal PowerShell sous Windows et redémarrez WSL :
~~~~powershell
wsl --shutdown
~~~~

2. Rouvrez votre terminal Ubuntu et vérifiez que le service redémarre bien :
~~~~bash
docker info >/dev/null 2>&1 && echo "Docker est opérationnel"
~~~~

### This document summarizes the essential commands to manage, verify, and use the native Linux Docker environment under WSL without relying on Docker Desktop.

---

## 1. Managing the Docker Service (via `systemd`)

The Docker daemon runs in the background thanks to `systemd`.

* **Check the service status:**
~~~~bash
sudo systemctl status docker
~~~~

* **Start the service manually (if stopped):**
~~~~bash
sudo systemctl start docker
~~~~

* **Stop the service:**
~~~~bash
sudo systemctl stop docker
~~~~

* **Enable automatic startup on WSL boot:**
~~~~bash
sudo systemctl enable docker
~~~~

---

## 2. Quick Verification without `sudo` (Ideal for scripts / pipelines)

To ensure the daemon is responding and the `/var/run/docker.sock` socket is active without requiring administrator privileges:
~~~~bash
docker info >/dev/null 2>&1 && echo "Docker is ready"
~~~~

---

## 3. Daily Usage Commands (Without `sudo`)

Since the user belongs to the `docker` group, all commands execute directly:

* **Test the installation with an ephemeral container:**
~~~~bash
docker run hello-world
~~~~

* **List running containers:**
~~~~bash
docker ps
~~~~

* **List all containers (active and stopped):**
~~~~bash
docker ps -a
~~~~

* **List available images:**
~~~~bash
docker images
~~~~

---

## 4. Quick Troubleshooting (In case of socket loss)

If the socket stops responding after a prolonged Windows hibernation:

1. Open a PowerShell terminal in Windows and restart WSL :
~~~~powershell
wsl --shutdown
~~~~

2. Reopen your Ubuntu terminal and verify that the service restarts properly :
~~~~bash
docker info >/dev/null 2>&1 && echo "Docker is operational"
~~~~
